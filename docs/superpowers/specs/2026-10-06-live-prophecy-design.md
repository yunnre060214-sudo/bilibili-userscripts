# B站直播预言第一版

目标是在 B 站桌面直播页直接查看和参与官方硬币预言，复用网页已有登录状态，无需账号配置。用户已批准官方组件方案，并要求直接发布到个人 GitHub 仓库。

## 设计

新增独立 `bilibili-live-prophecy.user.js`，版本 `0.1.0`。支持数字房间地址、短房间号及 `/blanc/<roomId>`。通过公开 `room_init?id=<roomId>` 的 `data.uid` 识别主播，使用 GET 且不携带账号凭据。官方预言页地址为 `https://live.bilibili.com/p/html/live-app-guessing-game/index.html?anchorId=<uid>#/`；历史路由为 `#/history`。

直播页右下方放置“预言”按钮，打开隔离样式的浮动面板。面板提供当前预言、历史、刷新、独立窗口、关闭操作。只有打开面板时加载官方 iframe；关闭后释放 iframe。选择及提交由用户在官方组件内完成。脚本自身不提交答案，不读取或保存 Cookie。

## 异常与兼容

主播识别失败时显示可重试的提示，历史入口仍然可用。请求超时为 8 秒。路由切换后更新主播，忽略旧请求结果。非直播路由和官方预言组件页不显示按钮。只运行在顶层页面，防止赛事页的内层直播 iframe 重复注入。支持窄屏、Escape 关闭及页面容器全屏。

不依赖外部运行时库，保持 BiliForge 等已有脚本不变。独立窗口入口始终使用官方 URL，供登录、嵌入加载异常等情况继续操作。

## 验证与发布

用真实 DOM 实现执行脚本，验证路由、主播识别、面板生命周期、历史、重试和异步竞态；接口响应使用本地 fixture，不进行硬币交易。执行已有回归测试，报告原有基线失败。上传脚本、测试及简明安装说明到 `yunnre060214-sudo/bilibili-userscripts` 的 `main`，回查 raw 文件与测试版本完全一致。

## 0.1.1 修订

用户确认此前成功提交是由手机网页跳转 App 完成，桌面仅能读取记录。官方 H5 的账号与查询可用不等于桌面参与流程完整；第一版缺少桌面确认弹窗，不能视为电脑参与已经验证。

保留入口，允许脚本在官方组件 iframe 的 document-start 阶段运行，通过 Webpack 模块加载时适配当前 SDK（模块 1171）。仅替换 showModal/showConfirm/showAlert/showToast 的用户界面，不改写账号、资格及请求实现。普通桌面和 PC_ROOM 使用网页确认窗口，App 与移动端保留原生桥接。实际参与仍由用户确认后执行官方逻辑，最终验收必须包含真实服务器结果及参与历史。
